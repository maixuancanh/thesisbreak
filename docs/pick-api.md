# Authenticated pick API foundation

These Node routes persist authenticated user picks. The local fictional preview is separate: no preview content is imported and the live market form calls these routes after explicit review. Google authentication and a migrated PostgreSQL database are required for creation; Tatum credentials are needed only when selecting Tatum. Missing configuration returns an error; it never creates a demo pick.

Every route resolves the durable session user on the server. Mutations require an exact `Origin` matching `APP_URL`. JSON bodies are capped at 16 KiB and parsed with strict schemas. Responses use `Cache-Control: no-store`; foreign and missing pick IDs both return 404. Database errors never return SQL or provider bodies.

- `GET /api/picks` returns the latest version of up to 100 owned picks, newest first. Pagination is not implemented.
- `GET /api/picks/{pickId}` returns one owned current version and its captured market fields.
- `POST /api/picks` accepts `{platform, nativeId, provider?, outcome, reason?, requestId}`. The server fetches the exact native market from the selected public API or Tatum, validates the outcome against that market, captures the real question and rules hash, and atomically creates the market identity, snapshot, pick version, idempotency receipt and outbox event. Client question, rules, identity and snapshot fields are rejected. The reason is optional and limited to 4000 characters. Missing rules fail closed with 422. Unavailable prices remain null. Prices are probabilities; `priceAsOf` stays null when the provider supplies no publication timestamp, distinct from retrieval time.
- `POST /api/picks/{pickId}/proposals` accepts `{baseVersion, requestId, changes: {outcome?, reason?}, reason}`. It returns a saved pending proposal with a server-controlled 15-minute expiry and explicit before/after values. Outcome changes must match the original captured market outcomes. This route is for a user-requested correction; evidence references are empty, and no model or external evidence validation is claimed.
- `POST /api/picks/{pickId}/confirm` accepts `{proposalId, requestId, confirmed: true}` after the caller has displayed and reviewed the saved proposal. Pick ownership, proposal ownership, pending status, expiry and base version are validated under database locks. Acceptance, the new version, idempotency receipt and outbox event commit in one transaction. No casual chat request directly changes a pick.

Request IDs are scoped to the durable user across mutation types. Identical retries replay the prior result; a changed payload with the same key returns 409. A confirmation with a new request ID cannot accept an already accepted proposal. Conflicting current versions return 409. Transaction locks serialize concurrent confirmations, preserving one version and one outbox event. The outbox is a durable event record; its presence does not prove a worker, remote memory sync or monitoring job ran.

The server may reuse a successful selected-provider catalog snapshot for up to 30 seconds. Its actual `fetchedAt` is retained; saving a pick does not imply a new upstream fetch on every click. This cache window is distinct from a price publication timestamp, which remains unknown when absent from the provider.

This is a bounded API foundation. Pause/archive/resume, watch configuration and execution, bookmark storage, historical-version responses, rejected proposals and live-provider/database acceptance are not implemented here. No route claims a watch is running. Do not connect model tools directly to trusted repository mutation primitives.

Validation: offline route tests cover unauthenticated access, mutation origin, supplied user IDs and session-scoped foreign details; unit tests cover strict inputs, real outcome names, missing rules and absent price timestamps. PostgreSQL tests cover changed idempotency payload, foreign ownership, invalid outcomes and competing proposal acceptance. They skip explicitly unless `TEST_DATABASE_URL` points at an isolated migrated test database. Fixture markets are fictional and used only inside tests.
