# Authentication

Google sign-in uses the installed `next-auth@4.24.15` package for OAuth, state/PKCE, CSRF cookies, encrypted JWT sessions and sign-out. Its Next route handler awaits Next 16 request APIs. No development bypass exists.

Configure server-only `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_SECRET` (at least 32 random characters), `DATABASE_URL`, and `APP_URL` (exact origin, no trailing slash). Production requires HTTPS. Register `<APP_URL>/api/auth/callback/google` in Google OAuth. The route sets NextAuth's canonical URL from APP_URL; configure NEXTAUTH_URL to the same value in deployment too. Apply database migrations first. Never expose these secrets as NEXT_PUBLIC variables. Missing configuration returns 503; database failure never grants an identity.

Google's verified provider account subject maps to `users.provider_subject` as `google:<sub>`. Email is neither authority nor identity namespace. The NextAuth JWT contains only the internal user ID and a cryptographically random session ID; the database stores its SHA-256 hash. Each session lookup joins the existing user and an unexpired, unrevoked session row. Maximum lifetime is seven days from login; JWT refresh does not extend database expiry. Sign-out uses native NextAuth CSRF checks, then revokes that session row. A request-local availability guard detects event errors that NextAuth catches internally; failed revocation replaces the native response with 503 and discards cookie-clearing/redirect headers. The UI displays a retry error. Session callback lookup failure similarly produces 503 instead of appearing signed out. Deleting the user cascades session removal. Administrators can revoke individual/all session rows. Signing out other devices requires revoking their rows; there is no account-management UI for this yet.

Server mutations must call `assertMutationOrigin(request)` and `requireUser()`, and derive ownership exclusively from the returned `id`. Never accept a client userId as authority. `getCurrentUser()` returns null for absent/revoked/expired sessions and throws on unavailable configuration. Neither helper imports browser preview state. Preview drafts remain browser-local and are never automatically imported into an account.

Tests cover config/origin/identity gates and actual NextAuth encrypted JWT tamper/expiry rejection. The PostgreSQL session integration test runs only with `TEST_DATABASE_URL` against a migrated disposable database. OAuth callback and signed-in browser behavior require real Google configuration and remain unverified until supplied. No credentials were supplied or searched for.
